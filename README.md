# Правила размещения товаров на складе

[![Tests](https://github.com/mnyug/lab2/actions/workflows/tests.yml/badge.svg)](https://github.com/mnyug/lab2/actions/workflows/tests.yml)

Библиотека на C# для распределения экземпляров товаров по контейнерам с помощью дерева правил. Учебный проект по объектно-ориентированному программированию в ИТМО, оформленный как отдельный репозиторий.

## Возможности

- Проверка вместимости контейнеров по весу и объёму.
- Проверка товарного соседства по группам категорий.
- Маршрутизация по категории с правилом по умолчанию.
- Последовательный обход правил контейнеров на палете до первого успешного размещения.
- Декораторы проверки срока годности и логирования результатов.
- Подменяемые часы и логгер для воспроизводимых тестов.
- Типизированные результаты успешного размещения и отказа.

## Сборка и тесты

Требуется **.NET SDK 10.0**. Проект не зависит от других лабораторных.

```bash
git clone https://github.com/mnyug/lab2.git
cd lab2
dotnet build Project.slnx --configuration Release
dotnet test Project.slnx --configuration Release
```

Это библиотека; сценарии использования представлены в тестах. Исполняемого приложения и команды `dotnet run` нет.

## Устройство

- `src/Lab2/Entities` — SKU, контейнер и отображение категорий на правила.
- `src/Lab2/Rules` — общий контракт `IRule` реализуют правила контейнера, палеты, маршрутизатора и декораторы.
- `src/Lab2/Services` — добавление товара, проверка соседства, репозиторий в памяти, часы и консольный логгер.
- `src/Lab2/Expiration` — условия для просроченных и непросроченных товаров.
- `src/Lab2/ValueObjects` — идентификаторы, категории, группы, срок годности и результаты размещения.
- `tests/Lab2.Tests` — xUnit-тесты соседства, вместимости, маршрутизации, логирования и разделения просроченных и свежих товаров.
- `docs/assignment.md` — исходное условие лабораторной.

## Решения в модели

Правила контейнеров и палет образуют композицию через `IRule`. `LoggingRule` и `ExpirationDateRule` оборачивают другие правила, добавляя поведение без изменения их реализации. Сервис тар получает репозиторий и проверку соседства через конструктор; время скрыто за `IDateTime`, логирование — за `ILogger`.

## Границы модели

Данные хранятся в памяти; база данных, конкурентное размещение и сетевой API не реализованы. Корректность вложенности дерева правил предполагается на стороне вызывающего кода, как допускает условие. Группы задаются по категориям; поиск тары выполняется до первого успеха, без оптимизации заполнения склада.
